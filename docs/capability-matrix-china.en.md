# Chinese-provider capability evidence matrix

[中文](capability-matrix-china.md)

The [machine-readable matrix](../data/capability-matrix-china.json) is a first-party documentation snapshot dated 2026-09-27. It is not runtime routing configuration or implementation acceptance. Every record has `live_validation: "not_run"`; account and regional entitlement remain `unknown`.

## Coverage and interpretation

Coverage includes all 21 bundled Qwen, DeepSeek, Kimi, MiniMax, and GLM/Z.AI profiles, 66 raw `[[model]]` rows, and 1,254 model-operation cells. There are also 606 independent service records, including 24 generation/edit records preserving the 12 independent image-model catalog rows. Complete coverage does not mean every cell has a positive finding.

- `operations` defines each operation, capability category and `model`/`service` scope. `sources` records the first-party URL, evidence date and relevant section.
- `profiles` preserves catalog path, protocol, URL, region and account product. Qwen Beijing, Singapore, Hong Kong and US, mainland GLM, international Z.AI and Coding Plan are distinct.
- A model's `cells` has `supported`, `unsupported` or `unknown`, with source IDs and an evidence basis. Cells inherit the date and live-validation status from their model record.
- `availability` separately records documented, unknown or `shut_down` status. Seven retired Kimi rows removed from runtime presets (six mainland, one international) remain in top-level `retired_models`, outside current coverage. Historical features do not override retirement; documented availability does not prove current account access.
- `services` uses independent operation identities. Embedding, knowledge-base, Batch, ASR, TTS, voice management, asynchronous audio and Realtime evidence never establishes those capabilities for a Chat model. `documented_models` contains verified service model examples or explicit allowlists, not an automatically complete catalog. An operation may set `profile_ids` when the documented route applies only to a bounded set of profiles.

`unsupported` requires an explicit first-party exclusion, rejection or ignored parameter, or retirement for a model's create operation. Missing documentation, failed fetches, similar model names and compatible protocols do not establish a negative claim. Unknown cells remain verification work rather than a reason to introduce compatibility fallbacks.

## Maintenance and checks

Read the official contract for the specific provider, region, model and protocol before changing cells, source dates or availability. Service-only evidence updates service records only; retain earlier source dates when adding a newer snapshot and date records no later than that snapshot. Use `profile_ids` when a service operation has evidence for only a bounded profile set. Add or rename model records with catalog changes. When explicit retirement evidence justifies removing a runtime preset row, move its evidence into `retired_models`.

Run `CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=2 cargo test --test capability_matrix_china`. Tests check complete profile/raw-model/image-model coverage, identity and region consistency, operation sets, unique records, valid states and first-party evidence, and the Batch/cache/realtime/Coding Plan boundaries plus Qwen Beijing RAG scope, HTTP TTS SSE semantics, and regional realtime-TTS boundaries, standalone ASR Realtime scope, and published Knowledge Search/Q&A prerequisites. They run offline without provider accounts and cannot establish live acceptance.

Qwen Audio Generation now has a separate Beijing workspace service record for `qwen-audio-3.1-tts-next`, with reference audio and signed URL output. This does not extend chat-model capabilities or validate account access. Older evidence retains its original date. [Official API](https://help.aliyun.com/en/model-studio/audio-generation-api).

LiveTranslate3.5/3.8 now have independent Beijing and Singapore workspace records. Their session fields and text events are distinct from Omni conversation and from each other. [Official guide](https://help.aliyun.com/en/model-studio/qwen3-5-livetranslate-flash-realtime).

Current GLM Knowledge documentation separately establishes file multipart upload via `upload_document/{id}`; this is not the deprecated Agent upload route. MiniMax HTTP TTS SSE has separate regional records backed by the official CLI parser; stream-option children and subtitle-event schemas are not inferred. The GLM Realtime SDK defines the function-output `call_id` field even though an older example omits it. These are documentation findings, not live acceptance.
