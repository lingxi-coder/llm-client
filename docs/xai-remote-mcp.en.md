# xAI Remote MCP (Responses)

This adapter configures an MCP server that xAI calls on the OpenAI-compatible xAI Responses route. Its xAI-specific configuration is `HostedTool::XaiRemoteMcp(XaiRemoteMcpConfig)` and contains only public connection settings: `server_label`, an HTTPS `server_url`, optional `server_description`, and optional `allowed_tools`. An empty `allowed_tools` list leaves all server-published tools available; a nonempty list restricts the available names.

The configuration is accepted only on an explicitly enabled xAI Responses profile: `provider_id = "xai"`, `protocol = "open_ai_responses"`, `base_url = "https://api.x.ai/v1"`, and `extra.xai_remote_mcp = "xai_responses"`. It does not switch the existing Grok Chat route to Responses. The encoded MCP tool uses the fields confirmed by xAI's example: `type: "mcp"`, `server_url`, and `server_label`, with `server_description` and `allowed_tools` included only when configured.

Supply the MCP token on every request through `RequestOptions::mcp_authorizations`, keyed by `server_label`. Immediately before sending, the client places the token in the matching Responses tool object's `authorization` field. The token is not part of `ChatRequest` and is not written to chat history or serialized request configuration. Before attachment processing or network dispatch, the client checks provider, protocol, official endpoint, capability marker, and credential labels. OpenAI and xAI MCP configurations cannot be mixed in one request, and an MCP request is not automatically retried across profiles.

Responses containing `mcp_call` or other unrecognized MCP output items retain those items as native `ProviderContent`. The client does not turn them into local `ToolUse`, execute server tools, or apply OpenAI's `mcp_approval_request` semantics to xAI. xAI explicitly says its Responses API does not currently support `require_approval` or `connector_id`, so this config type has neither field and rejects deserialization input containing unknown fields. Arbitrary MCP `headers` are not modeled yet.

xAI's specific [Remote MCP guide](https://docs.x.ai/developers/tools/remote-mcp) lists Responses API support and shows a request example. [Tool Usage Details](https://docs.x.ai/developers/tools/tool-usage-details) identifies the Responses `mcp_call` item as an MCP tool handled by xAI, and the [Streaming & Sync guide](https://docs.x.ai/developers/tools/streaming-and-sync) says MCP items are returned in Responses. The general [Responses REST reference](https://docs.x.ai/developers/rest-api-reference/inference/responses) still lists only function and web-search tools; this conflicts with the MCP-specific guide. The adapter follows the more specific MCP guide and does not infer additional fields it does not document. Live account and server acceptance has not been run.
