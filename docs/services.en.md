# Chat output contracts, caching and embeddings

[简体中文](services.md)

Version 0.2.0 uses `client.chat()` with `ChatRequest` / `ChatResponse`. There are no old type aliases or top-level Chat methods. Configuration v3 rejects older files without rewriting them.

## Structured output

Choose `OutputFormat::Text`, `JsonObject`, or `JsonSchema { name, schema, strict }`. This setting is independent of strict function tools. Encoders cover Chat Completions, Responses, Messages and Gemini GenerateContent, including hosted wrappers. An available encoder does not establish support for every compatible provider, model, account or region.

After completing the response, call `response.structured_json(&request.output_format)` or `response.structured::<T>(&request.output_format)`. Validation errors retain the entire response, including usage. Refused, truncated, tool-use and paused responses cannot be parsed as final structured results. For streaming, call `stream.collect_structured_json(&request.output_format)` or `stream.collect_structured::<T>(&request.output_format)`. The method waits for the terminal event, then validates and returns reconstructed text plus the original event list. `StructuredStreamError` retains received events; validation failures also retain the reconstructed response. Pass the same output contract used in the request. Use `stream.next()` when processing individual events instead.

Schemas are never rewritten or weakened. Known unsupported constraints and conflicting native output fields fail explicitly. The provider still checks model-specific restrictions. Local JSON Schema validation disables network/file resolution and rejects unknown format names. Token estimates count schemas and explicitly mark provider-injected formatting instructions as omitted.

Claude Messages compiles strict tool and JSON-output schemas under shared request-wide limits. Preflight allows at most 20 strict tools, 24 optional parameters across strict tools and JSON output, and 16 parameters using `anyOf` or type arrays. Ordinary non-strict tools do not count. The client never removes schema constraints to fit these limits. [Claude structured-output limits](https://platform.claude.com/docs/en/build-with-claude/structured-outputs).

Claude strict tool-input schemas and strict JSON output schemas fail preflight for recursive local `$ref`, a `$ref` used directly as an `allOf` branch, or a string `format` outside Anthropic's documented list (`date-time`, `time`, `date`, `duration`, `email`, `hostname`, `uri`, `ipv4`, `ipv6`, and `uuid`). Strict JSON output cannot be combined with citation-enabled native `document` or `search_result` input blocks (`citations.enabled: true`) or a final assistant-prefill message. These combinations fail before dispatch; JSON-like text in an ordinary text block does not enable citations. See Anthropic's [schema limitations](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [citations guide](https://platform.claude.com/docs/en/build-with-claude/citations), and [Messages prefill guide](https://platform.claude.com/docs/en/build-with-claude/working-with-messages).

OpenAI's `gpt-4o-2024-05-13` snapshot supports JSON Object mode but predates JSON Schema output support; that combination is rejected before sending. See the [OpenAI Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs).

On first-party DashScope OpenAI-compatible Chat routes, Qwen JSON Object mode requires the case-insensitive string `JSON` in explicit system or user text. Only `ChatRequest.system` and `ContentBlock::Text` in system/user messages count; assistant history, tool descriptions, and document or attachment payloads do not. The strict JSON Schema models currently verified in this client's active catalog are `qwen3.8-flash` and `qwen3.8-max`. Their optional properties and `additionalProperties` settings are preserved while the remaining supported schema subset is still validated. This policy does not extend to generic OpenAI-compatible gateways or Qwen Responses. See [Qwen Structured Output](https://help.aliyun.com/en/model-studio/qwen-structured-output).

On the first-party DeepSeek OpenAI-compatible Chat route, JSON Object mode also requires `json` in a system or user prompt. Preflight checks only explicit text in `ChatRequest.system` and system/user `ContentBlock::Text`, case-insensitively; assistant history, tool descriptions, and document or attachment payloads do not count. This rule applies only to the official HTTPS `api.deepseek.com` route. DeepSeek also recommends providing an example JSON shape and setting `max_tokens` reasonably; the client does not invent either. See [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/).

Official wire references: [OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs), [Claude](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Gemini](https://ai.google.dev/gemini-api/docs/generate-content/structured-output), [Kimi JSON Mode](https://www.kimi.com/help/kimi-api/api-model-capabilities), and [GLM Structured Output](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output).

## Prompt caching

`SystemBlock` now contains only text. `ChatRequest.prompt_cache` carries an optional automatic TTL and explicit breakpoints referencing tools, system blocks, or message content blocks in the original request. An empty policy preserves provider defaults; it does not disable automatic server caching.

OpenAI Responses uses separate native cache fields: GPT-5.6+ options control minimum lifetime, and documented models can also set independent maximum retention; see [OpenAI Responses prompt caching](openai-responses-prompt-cache.en.md). Other explicit policies are encoded for Messages-family protocols, Qwen Chat, and model-scoped OpenRouter Chat routes: OpenRouter Anthropic models accept five-minute or one-hour TTLs, the documented Alibaba/Qwen OpenRouter models accept only five-minute content breakpoints, and OpenAI GPT-5.6 and later accept only a 30-minute TTL. `CacheTtl::ThirtyMinutes` is rejected before dispatch on other routes. MiniMax allows only explicit five-minute breakpoints; other protocols reject explicit policies. Validation checks positions, duplicates, text-block eligibility, breakpoint limits and TTL ordering. Usage comes from actual provider reports; no cache hit or discount is assumed. The independent [Gemini Context Cache service](gemini-context-cache.en.md) supports explicit cached-content creation, lookup, listing, updates, and deletion on documented Developer API routes; other providers are not inferred from that support. See the [Claude cache contract](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [MiniMax cache contract](https://platform.minimax.io/docs/api-reference/anthropic-api-compatible-cache), and [OpenRouter prompt caching](openrouter-prompt-cache.en.md).

OpenRouter **gateway response caching** is separate from prompt caching. Set `RequestOptions.openrouter_response_cache` for Chat to `OpenRouterResponseCache::Enabled { ttl_seconds: Some(600), refresh: false }` to send the documented headers; the policy applies to profiles configured for official OpenRouter Chat Completions, Responses, or Anthropic Messages. `Disabled` explicitly opts out. TTL must be 1–86400 seconds, and refresh replaces only the matching request's entry. A remote preset that explicitly disables caching still takes precedence over an enabling request header. This policy requires the official OpenRouter HTTPS route and pins this request to one connection so failover cannot change its cache key. On that route, the client projects the documented `X-OpenRouter-Cache-Status: HIT|MISS` header into `ChatResponse.response_cache`; the observation may also include age, remaining TTL, and the source generation ID on hits. `ModelStream.response_cache()` exposes the same projection for streaming. Missing or unrecognized status headers produce `None`; zero usage is never treated as proof of a hit. [OpenRouter response caching](https://openrouter.ai/docs/guides/features/response-caching).

The official OpenRouter Embeddings route, `https://openrouter.ai/api/v1/embeddings`, accepts the same request-level policy and returns its observation in `EmbeddingResponse.response_cache`. Non-OpenRouter or non-official Embeddings routes reject the policy before dispatch; absent or unknown cache status is never inferred as a hit.

## Text embeddings

`client.embeddings().embed(profile, request, options)` uses the independent endpoint and authentication in `ProviderProfile.embeddings`. `ServiceSetting::Inherit`, `Enabled(route)` and `Disabled` distinguish inheritance, replacement and explicit disabling across configuration reloads.

`EmbeddingRequest` contains `model`, `input: Vec<String>`, optional `dimensions` and optional `task`. Implemented wires are OpenAI, OpenRouter, Gemini batchEmbedContents and Qwen DashScope. OpenRouter maps `RetrievalQuery` / `RetrievalDocument` to `input_type: search_query` / `search_document` and requests float vectors; other tasks are rejected before sending. OpenAI, OpenRouter, Gemini and GLM presets contain explicit operation endpoints. Qwen requires the caller's workspace-specific endpoint. Model IDs are sent directly to the embedding service without using the Chat catalog.

The built-in OpenRouter profile also configures an independent `models_endpoint`. `client.embeddings().list_models("openrouter", offset, limit, options)` follows the documented `offset`/`limit` pagination (`limit` 1–1000) and returns IDs, names, context lengths, input modalities, native metadata, and `total_count` / `next_offset` when available. This directory is for discovery; it does not modify the Chat catalog or infer parameter support.

Gemini has its own `models_endpoint` and typed `list_gemini_models` / `get_gemini_model` methods. They expose models explicitly advertising `embedContent`, preserving exact resource IDs, base model IDs and native metadata. Pagination uses a native token bound to the original request scope; an empty filtered page may still have a continuation, and the client never fetches it automatically. See [Gemini Embeddings](gemini-embedding.en.md) for examples and account-scope limits. Independent embedding directories for other providers remain subject to verification.

Vectors are returned in input order. Invalid counts, duplicate/missing/out-of-range indices, non-finite values, empty vectors and inconsistent dimensions fail explicitly. The client never normalizes, truncates, splits or retries embedding requests. Reported model and usage remain optional; absent values are not guessed. Usage retains native fields and distinguishes missing, partial, complete and invalid reports. Request and response limits are 64 MiB; deadlines also cover injected transports. The generic `EmbeddingRequest` accepts text; Gemini Embedding 2 multimodal inputs use a separate provider-specific API, with no support inferred for other providers. See [Gemini Embeddings](gemini-embedding.en.md).

Official references: [OpenAI](https://developers.openai.com/api/reference/resources/embeddings/methods/create), [Gemini](https://ai.google.dev/api/embeddings), [Qwen](https://help.aliyun.com/en/model-studio/text-embedding-synchronous-api), [OpenRouter Embeddings](https://openrouter.ai/docs/api/api-reference/embeddings/create-embeddings) and its [model directory](https://openrouter.ai/docs/api/api-reference/embeddings/list-all-embeddings-models).

## Native output items

OpenRouter Responses / Messages have typed regex tool-search and hosted-shell settings, including deferred tools, scoped container references and single-attempt dispatch. See [OpenRouter server tools](openrouter-server-tools.en.md). These two tools are unavailable on Chat Completions.

`ChatRequest.tools` declares functions executed by the host; `ChatRequest.hosted_tools` declares provider-executed tools. In addition to web search, file search and OpenAI Code Interpreter, Gemini GenerateContent provides `HostedTool::GeminiCodeExecution`, `GeminiUrlContext`, and `GeminiMapsGrounding(GeminiMapsGroundingConfig { enable_widget, lat_lng })`. These Gemini options are enabled only on the exact first-party Gemini Developer API `GeminiGenerateContent` route; Vertex, gateways, other custom endpoints and unknown models are rejected before attachment preparation or credential use. Supported model IDs are `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-2.5-pro`, `gemini-3-flash-preview`, `gemini-3.1-flash-lite`, `gemini-3.1-pro-preview`, `gemini-3.5-flash`, `gemini-3.5-flash-lite`, `gemini-3.6-flash`, `gemini-3.7-flash`, and `gemini-3.8-flash`. Client-executed functions can be combined with these built-in tools on Gemini 3 models; requests enable Google's server-side tool context circulation and `VALIDATED` function-calling mode. Gemini 2.5 combinations fail preflight. Maps accepts optional `lat_lng` and `enable_widget` settings and rejects multimodal input. Maps with Google Search is enabled only for Gemini 3.5 Flash and later Flash models listed above. Multiple new Gemini built-in tools are not combined in one request. Requests using Gemini hosted tools are pinned to the selected connection and are not automatically resent after a network error, server error or missing file, avoiding duplicate server-side execution. Duplicate hosted kinds fail before attachment resolution or HTTP.

The OpenAI Responses profile supports `HostedTool::CodeInterpreter(CodeInterpreterConfig { memory_limit: Some(CodeInterpreterMemoryLimit::FourG), ..Default::default() })`. With no `container`, this uses OpenAI's automatic container; omitting the memory tier leaves the server default, and the supported tiers are 1g, 4g, 16g, and 64g. `CodeInterpreterConfig::with_files()` mounts existing, account-scoped OpenAI Files API references as `container.file_ids`; provide the same stable `RequestOptions.file_account_scope` used to create them. The client checks connection identity, readiness, and expiry before dispatch. To reuse an existing container, pass its `OpenAiContainerRef` with `CodeInterpreterConfig::with_container()` and provide the same stable `RequestOptions.account_scope` used for the reference. Explicit reuse is limited to the official OpenAI Responses endpoint and sends the container ID. It cannot be combined with the automatic-only `memory_limit` or `files` settings; attach files to an explicit container through the [Containers service](openai-containers.en.md) before the Responses call. That service also configures `expires_after` when creating explicit containers; the Responses automatic-container config has no expiry option, and expired containers are rejected by the provider. Requests include `code_interpreter_call.outputs`, and returned call items survive as `ProviderContent`. Code Interpreter requests are pinned and are not automatically replayed or failed over after dispatch. Token cost estimates exclude tool and container charges; the provider checks model and account support. [Official OpenAI Code Interpreter guide](https://developers.openai.com/api/docs/guides/tools-code-interpreter).

Responses hosted-tool and unknown output items survive as `ProviderContent`. Streaming deduplicates each output index between `output_item.done` and the final response. Gemini `executableCode`, `codeExecutionResult`, `inlineData`, `toolCall`, and `toolResponse` Parts are also retained as native JSON and can be replayed unchanged on the same Gemini protocol; they are not converted into host-executed function calls. URL Context and Maps candidate metadata stays in `ChatResponse.web_search.metadata`, not in content Parts. Maps source URIs, titles, place IDs and attribution metadata are retained; renderers still need to follow Google's Maps attribution requirements. MCP approval requests produce `StopReason::Other("requires_action")`; the host handles approval and continuation. `HostedTool` is a shared input type, while each codec only encodes its explicitly supported tools.

## Responses continuation

Set `RequestOptions.account_scope` to a stable, non-secret identity for the provider account. A completed `ChatResponse.continuation` contains a `ContinuationRef`; for streaming, consume the terminal event before calling `ModelStream::continuation()`. Put that reference in the next `ChatRequest.continuation`, send only new input in `messages`, and use the same account scope. If the first request used a fallback, select its `response.executed_profile` for the next call.

The reference binds provider, profile, endpoint, wire model, account and Qwen retrieval workspace. A mismatch fails before attachment resolution or HTTP. Continuations do not fail over or automatically resubmit after a file 404. Without `account_scope`, the raw `response_id` remains visible but no reusable reference is returned. Direct codec decoding has no client route and cannot construct one. A Responses-compatible profile must still opt in with `extra.supports_previous_response_id = true`.
